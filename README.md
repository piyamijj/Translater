# PolyGlot Live AI

Production-ready, ultra-low-latency real-time voice translator — captures
speech in any source language, transcribes + translates it instantly via a
pluggable AI backend (Google Gemini, Groq, or OpenAI), and speaks the
translation back out loud. Ships as a **web app (Vercel)** and a **native
Android app (Capacitor)** from a single Next.js codebase.

## Features

- **Bring-your-own-key**: users paste their own Gemini / Groq / OpenAI API
  key into the Settings modal. Keys live only in the browser's
  `localStorage` — never logged, never sent to any server but the provider
  itself.
- **Two capture modes**: push-to-talk, and hands-free continuous mode with
  energy-based voice-activity detection that auto-translates on pauses.
- **Automatic provider fallback**: if the preferred provider fails, the app
  transparently retries with any other configured provider.
- **Fully audible translation**: every translated result is spoken aloud via
  TTS automatically, and both the original and translated panels have their
  own read-aloud + copy buttons.
- **Modern, mobile-first, dark UI** with a live audio waveform visualizer.
- **15 target languages**, defaulting to Turkish, switchable at any time.

## Tech stack

Next.js 14 (App Router, TypeScript, Tailwind CSS) · Capacitor (Android) ·
Shadcn/Radix UI · Framer Motion · Lucide icons · Zustand (persisted) ·
Web Audio API / MediaRecorder · `@google/genai` · `groq-sdk` · Web Speech API.

## Getting started (web)

```bash
npm install
npm run dev        # http://localhost:3000
```

Open Settings (gear icon) and paste at least one provider API key to start
translating.

## Deploying to Vercel

The repository is linked to Vercel for continuous deployment: every push to
`main` deploys to production automatically. `GEMINI_API_KEY` /
`GROQ_API_KEY` / `OPENROUTER_API_KEY` are configured as Vercel project
environment variables purely as an **optional fallback** for the
`/api/translate` and `/api/tts` server routes — the default, primary path
for end users is entirely client-side with their own key and never touches
these.

## Building the Android APK

Handled automatically by `.github/workflows/build-apk.yml` on every push to
`main` and on version tags (`vX.Y.Z`), which additionally publishes the APK
to GitHub Releases. See `android/README.md` for why the native project is
generated by CI rather than hand-committed, and how to build locally.

To produce a **signed release APK** instead of a debug-signed one, add these
repository secrets (Settings → Secrets and variables → Actions):

- `RELEASE_KEYSTORE_BASE64` — your `.keystore`/`.jks` file, base64-encoded
- `RELEASE_KEYSTORE_PASSWORD`
- `RELEASE_KEY_ALIAS`
- `RELEASE_KEY_PASSWORD`

Without these, CI builds a debug-signed APK that installs and runs fine for
testing/sideloading.

## Security notes

- API keys entered in the Settings modal are stored only in `localStorage`
  and are used for **direct client-side calls** to each provider — this app
  never has a backend database and never logs request bodies.
- The two `/api/*` routes are optional, stateless pass-throughs for CORS
  edge cases; they never persist anything either.
